# SortView Collector v1 runtime dependencies -- deliberately MINIMAL,
# matching what the deployed runtime actually imports today: collector/*.py
# (stdlib + requests, which itself depends on urllib3/certifi/idna/
# charset-normalizer) PLUS the canonical parser runtime now deployed
# alongside it (agent/parser/*.py + agent/logger_config.py -- see
# collector/deploy_manifest.py -- which import pandas). This is NOT the
# repository's own requirements.txt (that file is for the Streamlit
# dashboard + FastAPI backend, which the collector must never need -- see
# collector/preflight.py's no_direct_database_dependency check, which
# exists specifically because the live AMH machine's agent venv was once
# found with psycopg2-binary/SQLAlchemy installed despite never using
# them, most likely from installing the full repo requirements file
# instead of a minimal one like this).
#
# requests/urllib3 versions pinned to what was directly verified running
# in live NBPL production during the Phase 1 AMH machine audit (Python
# 3.14.3, requests 2.33.1, urllib3 2.6.3) -- not merely what happens to
# resolve in this repo's own development virtual environment.
#
# pandas was added by the parser-parity phase (PR #25), which wired
# collector/parsers.py to the real agent/parser/* modules -- those import
# pandas directly (see agent/parser/checkins.py etc.). No live-AMH-audited
# pandas version exists for the collector specifically (pandas was never
# part of Phase 1's audit of the legacy pipeline's own venv), so this is
# pinned to the exact version this repo's own requirements.txt already
# uses and this whole engagement's test suite already runs against
# (2.3.3), rather than an arbitrary or unverified choice. Its own
# transitive dependencies (numpy, python-dateutil, pytz, tzdata) are left
# unpinned here and resolved by pip, the same way requests' own
# transitive dependencies already are above.
